# 2026-10-04 記事ページ・記事一覧のデザインをほかのページにそろえる

- 対応日: 2026-10-04
- 対象: 記事ページ（`/products/[slug]` など）、記事一覧（`/products` など）、ヘッダー、記事本文のスタイル

## 概要と原因

トップ・経歴・受賞歴などのページは、以前の作業（コミット `9802192`・`3dc9f53`）でトップページの雰囲気にそろえて作り直していた。

- クリーム色の見出し帯（`PageHero`）
- 枠線なしで、オレンジがかった柔らかい影の角丸カード（`CARD_SHADOW`）
- 丸い「ピル型」のボタンやラベル

一方、**記事ページと記事一覧は作り直しの対象から外れていて、Figma で作った当初の見た目のまま**だった。そのため、同じサイトの中で2種類のデザインが混ざっていた。

| 場所 | 作り直し前の見た目 | ほかのページ |
|---|---|---|
| 記事ページの見出し | 白地に黒い小さめのタイトル。英字ラベルなし | クリーム色の見出し帯に、英字ラベルと大きな見出し |
| 記事ページの目次 | 黒い細枠の四角い箱。見出しは「あらすじ」 | 角丸で影つきのカード |
| 記事本文の h2 | 太字と灰色の下線だけ | 小見出しはオレンジの左線（トップの Skills） |
| 記事一覧のカード | 灰色の細枠と薄い影、詰まった余白 | 枠なしでオレンジがかった影、広めの余白、「記事を読む ›」 |
| 検索バー・ページ送り | 灰色の小さな四角い部品 | オレンジのピル型ボタン |
| タグ | 青緑の四角いラベル | 受賞歴の技術名はクリーム色のピル型 |
| ヘッダー | 記事ページでは「制作物」などがハイライトされない | 今いるページがオレンジでハイライトされる |

## 放置するとどうなるか

- ページを移るたびに見た目の雰囲気が変わり、作りかけのサイトに見える。ポートフォリオとして見てもらう場面では、デザインへのこだわりが伝わらない。
- 記事ページでは、ヘッダーのどこもハイライトされないので、今どの種類の記事を読んでいるのか分かりにくい。
- 部品ごとに見た目の定義がばらばらなので、今後デザインを直すときに、どれに合わせればよいか迷う。

## どう対処したか

変更する項目は事前に選んでもらった。**記事内の画像はそのまま**（角丸の追加などはしない）、**記事一覧の背景はクリーム色にしない**、**スマホ幅のカードは今の見た目（枠なし・下に 40px の余白）のまま**。

### 記事ページ

**元のデザイン（中央寄せ・白地・本文の列の上にタイトル）を尊重し、雰囲気合わせは小さな変更にとどめた。**

最初は、ほかのページと同じクリーム色の見出し帯（`PageHero`）に置き換え、本文を見出し帯の横余白にそろえて左寄せにし、目次をトップのカードと同じ大きな影のカードにした。しかし、「記事を読むには元のデザインのほうが適している」「元は中央寄せだったのに左寄せになっている」というフィードバックを受け、次の形に作り直した。

| 変更 | 内容 |
|---|---|
| 構成 | 元のとおり、本文の列（最大 768px）と目次を画面の中央に置き、白地のまま見出しから本文まで一続きにした |
| 英字ラベル | タイトルの上に、ほかのページの見出しと同じオレンジの小さな英字ラベル（Products / Blog / Books）を置いた。どのジャンルの記事かが分かる。このために、各ジャンルのルート（`/products/[slug]` など）から `PostDetailPage` に `genre` を渡すようにした |
| 目次 | 元の「枠線の箱」（見出しは「あらすじ」）のまま、濃い灰色の枠線を、記事一覧のカードと同じ薄い暖色の枠線（`--softborder`）・角丸・控えめなオレンジの影にした |
| 本文の h2 | [`globals.css`](../src/app/globals.css) の `.markdown-preview h2` を、灰色の下線からオレンジの左線（トップの Skills の小見出しと同じ）に変えた |
| タグ | 記事一覧と同じピル型（部品を共有しているため） |
| 一覧へ戻るボタン | 日付の行の右に、トップページのボタンと同じピル型の「← 制作物の一覧へ」を置いた（ジャンルに合わせて「ブログの一覧へ」などに変わる）。最初の作り直しで見出し帯の中に置いたものが好評だったため、元のデザインに戻した後も残した |
| 日付の折り返し | 各日付に `whitespace-nowrap` を付け、行を `flex-wrap` にした。スマホ幅で「2026年10月02 / 日」のように日付の途中で切れていたのが、日付・ボタンの単位で次の行へ送られるようになった |

本文のスタイル（`.markdown-preview`）は、**管理画面のプレビューと年表の詳細ページ**でも使っているので、h2 の見た目はそこでも同じように変わる。

### ヘッダー

[`SelectBar.tsx`](../src/components/SelectBar.tsx) に `isNavActive()` を追加した。これまではパスの完全一致でハイライトしていたので、記事ページや年表の詳細では、どの項目も光らなかった。そのページの配下（`/products/bingo2` なら「制作物」）にいるときもハイライトするようにした。ホーム（`/`）は、すべてのパスが `/` で始まってしまうので、完全一致のときだけにしている。スマホのメニュー（`SideBar`）も同じ関数を使う。

### 記事一覧

| 変更 | 内容 |
|---|---|
| カードをトップのカード風に（sm 以上） | [`Card.tsx`](../src/components/Card.tsx) の角を `rounded-3xl` にし、余白を 16px に広げた。影は、元のデザインの「薄い枠線＋`shadow-sm`（黒 5%）」と同じ形・同じくらい控えめな強さのまま、色だけをオレンジ（10%）にした（最初はトップのカードと同じ大きく広がる影にしたが、一覧で何枚も並ぶと主張が強すぎるというフィードバックで戻した）。タイトルは太字で、カードにホバーするとオレンジになる。説明文はトップと同じ薄い灰色にした。日付の行の上に薄い区切り線を引き、「記事を読む ›」（`ReadMore`）を付けた。カードの幅と並べ方は変えていない |
| 「記事を読む ›」の置き場所 | タブレット〜デスクトップ（sm〜xl）は、テキスト列が 341px しかなく日付と同じ行に入りきらないので、右列のサムネイルの下に置いた。2xl はテキスト列が 486px あるので、日付と同じ行の右端に置いた。スマホ幅では出さない（スマホのカードの見た目は変えないため） |
| 検索バーをピル型に | [`SearchBar.tsx`](../src/components/SearchBar.tsx) を、白地に薄い枠線の丸い形にし、検索ボタンだけをオレンジの丸にした |
| ページ送りをピル型に | [`PageSelectButton.tsx`](../src/components/PageSelectButton.tsx) を 28px の円にし、今のページを塗りつぶしのオレンジにした。押せないボタンは灰色で塗らずに薄く表示する。管理画面の一覧のページ送りも同じ部品なので一緒に変わる |
| タグをピル型に | [`TagLabel.tsx`](../src/components/TagLabel.tsx) を、受賞歴の技術名と同じクリーム色＋薄い枠線の丸いラベルにした。記事ページ・検索バー・管理画面のタグも同じ部品なので一緒に変わる |

読み込み中の骨組み（[`PostListSkeleton.tsx`](../src/components/PostListSkeleton.tsx)）も、新しいカードの構造（日付の区切り線、右列の「記事を読む ›」）と、新しい検索バー・ページ送り・タグの大きさに合わせた。カードの外枠などは `Card.tsx` の定数を共有しているので、自動で追従する。

### 追加対応: 「タグで絞り込む」を押すとタグの選択画面が開くようにした

**概要と原因**: 検索バーは、右端の虫眼鏡だけがボタンで、「タグで絞り込む」の文字や選択中のタグの部分を押しても何も起きなかった。制作時は「虫眼鏡を決定ボタンのように使う」想定だったが、見た目は検索欄なので、利用者は文字の部分を押す。そのため、どこを押せばよいか分かりにくかった。

**放置するとどうなるか**: タグで絞り込めることに気づかれず、絞り込み機能が使われない。押しても反応しないので、壊れていると思われる。

**どう対処したか**（[`SearchBar.tsx`](../src/components/SearchBar.tsx)）:

- バー全体を押すと、タグの選択画面が開くようにした。虫眼鏡は「押すと検索できる」ことを示すアイコンとして残した（押せば同じく開く）。
- バーの中には選択中タグの「×」ボタンがあり、`<button>` の中に `<button>` は入れられない。そのため、外側は `role="button"`・`tabIndex={0}` の div にし、Enter・Space キーでも開けるようにした。
- 「×」は `TagLabel` 側で `stopPropagation` しているので、押してもバーのクリックとして扱われず、選択画面は開かずにタグを外すだけになる。
- ホバー・キーボードのフォーカスで枠をオレンジにして、押せる場所だと分かるようにした。読み上げ用のラベルは「タグで絞り込む（選択中: React）」のように、選択中のタグを含む。

**確認したこと**: 手元に中継サーバーを立て、ヘッドレス Chrome で、iframe 内の本物のページを外側から操作した。

| 操作 | 結果 |
|---|---|
| 「タグで絞り込む」の文字を押す | 選択画面が開く |
| 選択中のタグの部分を押す | 選択画面が開く |
| バーにフォーカスして Enter | 選択画面が開く |
| 選択中のタグの「×」を押す | 選択画面は開かない |

## 確認したこと

`pnpm preview` で、ヘッドレス Chrome を使って撮影した。確認のため、本番の画像を手元のローカル R2 に一時的にコピーし、確認後に消した。

| 画面 | 結果 |
|---|---|
| 記事一覧 1280px | 薄い暖色の枠線と控えめなオレンジの影・角丸・余白。タグ・検索バー・ページ送りがピル型、今のページがオレンジ |
| 記事一覧 768px・1536px | 768px は1列で「記事を読む ›」がサムネイルの下。1536px は日付と同じ行の右端 |
| 記事一覧 390px | カードは枠なしの見た目のまま。「記事を読む ›」は出ない |
| 記事ページ 1280px・390px | 元どおり中央寄せ。タイトル上のオレンジの英字ラベル、暖色の枠の目次、本文の h2 のオレンジの左線。ヘッダーの「制作物」がハイライトされる |
| 読み込み中の骨組み 1280px | 本物のカードと幅・高さ・次のカードの開始位置まで一致 |

記事内の画像の角がわずかに丸いのは、もともとの設定（`.markdown-preview img` の `border-radius: 0.375rem`）で、今回は変えていない。

**未確認**: 管理画面（プレビュー・タグ管理・一覧のページ送り）での見え方。ログインが必要なため、デプロイ後に確認する。

**別に見つかった既存の問題（対応済み）**: スマホ幅（390px）の記事ページで、日付が「2026年10月02 / 日」のように途中で折り返されていた。元のデザインのときからある挙動だったが、依頼を受けて上表の「日付の折り返し」のとおり直した。1280px では日付とボタンが1行、390px では「公開日」/「最終更新日・ボタン」の2行、360px では日付・ボタンがそれぞれの単位で折り返すことを撮影して確かめた。
