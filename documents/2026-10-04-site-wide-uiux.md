# 2026-10-04 サイト全体（管理画面を含む）の UI/UX 改善

- 対応日: 2026-10-04
- 前段の作業: [検索バーとタグの選択画面の UI/UX 点検と修正](./2026-10-04-design-unification.md#追加対応-検索バーとタグの選択画面の-uiux-点検と修正)

検索バーとタグの選択画面で見つけた問題（押しにくい・反応がない・空の画面・キーボードや読み上げソフトで使えない）と同じ観点で、公開ページと管理画面のすべてを点検して直した。

## 点検のしかた

コード全体から、問題になりやすい書き方を機械的に洗い出し（モーダル、`router.push`、`window.confirm`、`div` の `onClick`、`focus:outline-none`、ラベルのない入力欄など）、該当する部品を1つずつ読んだ。公開ページは、修正後にヘッドレス Chrome で実際に操作して確かめた。

## 見つかった問題と対処

### 1. モーダル（ダイアログ）がキーボード・読み上げソフトで使えない

**概要と原因**: タグ管理画面の「タグを編集」「他ジャンルのタグを追加」は、タグの選択画面を直す前と同じ状態だった。開いてもフォーカスが背後に残る、Tab で背後を移動する、Esc で閉じない、背後がスクロールする、読み上げソフトにダイアログと伝わらない。

**放置するとどうなるか**: キーボードだけで管理画面を操作できない。読み上げソフトでは、何が開いたのか分からない。

**対処**: タグの選択画面に入れた処理を、共通のフック [`src/lib/useDialog.ts`](../src/lib/useDialog.ts) に切り出した（フォーカスの移動・トラップ・復帰、Esc で閉じる、背後のスクロール停止）。タグの選択画面・タグの編集・他ジャンルのタグ追加・スマホのメニューで使う。各ダイアログには `role="dialog"`・`aria-modal`・見出し（`aria-labelledby`）を付けた。

### 2. スマホのメニューが、閉じているときもキーボードで移動できてしまう

**概要と原因**: [`SideBar.tsx`](../src/components/SideBar.tsx) は、閉じているときも `transform` で画面の外に隠しているだけだった。そのため、Tab キーで見えない場所のリンクにフォーカスが移った。開いたときもフォーカスが中に移らず、Esc で閉じなかった。ハンバーガーボタンは、メニューが開いているかどうかを伝えていなかった。

**放置するとどうなるか**: キーボードで操作すると、フォーカスが見えない場所へ消えて、どこにいるか分からなくなる。

**対処**: 閉じているときは `inert` を付け、中のリンクにフォーカスが移らないようにした。開いているときは `role="dialog"` にして `useDialog` を使う。閉じたら、フォーカスはハンバーガーボタンへ戻る。ハンバーガーには `aria-expanded`・`aria-controls` を付けた。

### 3. 「押せない」見た目のボタンが押せてしまう

**概要と原因**: [`SquareButton`](../src/components/SquareButton.tsx) と [`RoundButton`](../src/components/RoundButton.tsx) の `state="Disabled"` は色を変えるだけで、実際には押せた。タグ管理の「保存」「追加」は、保存中やタグ名が空でも押せ、「このジャンルから除外」「完全に削除」も処理中に押せた。

**放置するとどうなるか**: 空の名前を送ったり、連打で同じ処理が何度も走ったりする。

**対処**: 両方のボタンに、本当に押せなくする `disabled` を追加した（薄く表示される）。保存中や入力が空のときは `disabled` にした。`state` は「色」の意味のまま残している（キャンセルボタンや、選ばれていないタブの見た目にも使っているため）。

### 4. 選択中の状態・今いるページが、色でしか分からない

**概要と原因**: 管理画面の状態タブ（未公開・公開中・アーカイブ済）、タグ管理のジャンルタブ、ヘッダーのナビの「今いるページ」は、色だけで示していた。

**対処**: `SquareButton` に `pressed`（`aria-pressed`）を追加し、タブで使った。`RoundButton` はリンクで選択中のとき `aria-current="page"` を付ける。ナビには `aria-label="サイト内のページ"` を付けた。

### 5. 入力欄とラベルが結び付いていない

**概要と原因**: [`InputField`](../src/components/InputField.tsx) と、年表エディタで `FormLabel` と組み合わせている選択欄・入力欄は、ラベルが `<span>` で、入力欄と結び付いていなかった。日記の本文やラベル管理の入力欄には、名前がまったくなかった（`placeholder` だけ）。エラーも、色付きの文字で出すだけだった。

**放置するとどうなるか**: ラベルを押しても入力欄に移らない。読み上げソフトでは、何の欄か・エラーがあるかが分からない。

**対処**:

- `InputField`: `useId` で、ラベル（`<label htmlFor>`）と入力欄を結び付けた。必須（`aria-required`）、エラーの有無（`aria-invalid`）、エラー文（`aria-describedby`）も入力欄に付けた。
- `FormLabel`: `htmlFor` と `errorId` を渡せるようにした。年表エディタの各選択欄・入力欄に id を振って結び付けた。
- 日記の本文には `<label>`、ラベル管理の入力欄には `aria-label` を付けた。
- エラーの表示（フォームのエラー、保存・削除の失敗、タグ管理のエラー）には `role="alert"` を付け、出たことをすぐ読み上げる。保存結果のメッセージには `role="status"` を付けた。

### 6. 画面の切り替え中に反応がない

**概要と原因**: 管理画面の状態タブと、日記の「この日の日記を書く」は、押してから次の画面が届くまで何も変わらなかった。記事の詳細ページ、年表、管理画面の各ページにも `loading.tsx` がなく、休止明けは固まって見えた（記事一覧で直したのと同じ問題）。

**対処**:

- 状態タブ: 検索バーやページ送りと同じく `startTransition` の `isPending` で `data-list-pending` を付け、読み込み中はカード一覧を薄くする。
- 日記の日付ボタン: 読み込み中は「開いています…」にして押せなくする。
- 共通の読み込み中表示 [`PageLoading`](../src/components/PageLoading.tsx)（回転する輪と「読み込み中です…」）を作り、次の場所に `loading.tsx` を置いた。

| 場所 | 対象 |
|---|---|
| `(public)/products|blogs|books/[slug]/loading.tsx` | 記事ページ（一覧は既存の `(list)/loading.tsx`） |
| `(public)/history/loading.tsx` | 年表の一覧と詳細 |
| `admin/(list)/loading.tsx` | 管理画面の一覧（ヘッダーは表示したまま中身だけ差し替わる） |
| `admin/loading.tsx` | 管理画面の作成・編集ページ |

### 7. 空の状態で何も表示されない

**対処**:

- 管理画面の記事一覧: 0件のときに「未公開の記事はありません。」など（状態に合わせた文言）を出す。タグで絞り込んでいるときは、「選択したタグに一致する記事はありません。」と「絞り込みを解除」（状態は残す）を出す。
- タグ管理: タグが1つもないジャンルでは、何をすればよいかの案内を出す。

（年表・日記・ラベル管理には、もともと「まだ〇〇がありません。」の表示があった。）

### 8. 取り消せない操作に確認がない

**概要と原因**: 年表の削除・ラベルの削除には確認があったが、記事の「アーカイブ」、タグの「このジャンルから除外」「完全に削除」には確認がなく、押した瞬間に実行された。

**対処**: 既存の削除と同じく `window.confirm` で、何が起きるかを書いた確認を出してから実行する。

### 9. タグの並べ替えがマウスでしかできない

**概要と原因**: タグ管理の並べ替え（dnd-kit）は、マウス・タッチ用の `PointerSensor` しか使っていなかった。

**対処**: `KeyboardSensor` を追加した。画像（つかむ場所）に Tab で移動し、Space で持ち上げ、矢印キーで動かし、Space で置く（Esc で取り消し）。つかむ場所には操作方法を含む `aria-label` と、キーボード操作中のフォーカス枠を付けた。タグ名のボタンにも「〇〇を編集」の名前を付けた。

### 10. 年表の編集画面の表示崩れ（追加対応）

**概要と原因**: 年表の出来事の編集画面で、「ラベル」の欄が右側の列にはみ出し、「制作物の記事（slug）」に重なっていた。「表示用の日付」（`InputField`）は `shrink-0`（縮まない）なので、同じ行に並べると行の幅を取りきり、「ラベル」の欄が押し出されていた。説明文（注釈）と「年表での表示プレビュー」で縦にも詰まっていた。

**放置するとどうなるか**: 「ラベル」の選択欄が見えない・押せない状態になる。

**対処**（[`HistoryEventEditor.tsx`](../src/components/HistoryEventEditor.tsx)）:

- 「表示用の日付」と「ラベル」を、それぞれ `flex-1 min-w-0` の枠に入れて半分ずつの幅にした。
- 依頼により、注釈3つ（並び順・期間・slug の説明）と「年表での表示プレビュー」を削除した。
- 詳細（Markdown）のラベルの文言を「書くと年表から詳細を開けるようになります」に変えた（11 で詳細をダイアログ表示にしたため）。

**未確認**: 管理画面のためブラウザでは確認していない。

### 11. 年表の出来事の詳細をダイアログで表示する（追加対応）

**概要と原因**: 制作物の記事がない出来事の「詳しく見る →」とタイトルは、別ページ（`/history/[id]`）へ移動していた。

**放置するとどうなるか**: 年表を読み進める途中で毎回ページが切り替わり、戻るたびに読んでいた位置を探し直すことになる。

**対処**: 年表のカード（[`HistoryEventCard.tsx`](../src/components/HistoryEventCard.tsx)）に「くわしく ›」を置き、詳細ページと同じ内容（日付・時代・ラベル・タイトル・概要・画像・本文）をポップアップで表示するようにした（[`HistoryEventDetailDialog.tsx`](../src/components/HistoryEventDetailDialog.tsx)）。

- **ほかのページの「くわしく」と同じ部品で開く**: 最初は専用のダイアログを作ったが、経歴ページなどのカードの「くわしく」（[`MoreDetails`](../src/components/MoreDetails.tsx)）と開き方・見た目が違っていた。具体的には、ふわっと拡大する表示・ぼかした背景・上に全幅の画像・区切り線・スクロールしても残る白い丸の閉じるボタンがなかった。そこで `MoreDetails` をそのまま使う形に作り直した。開くボタンも、ほかのカードと同じオレンジの「くわしく ›」になる。タイトルはほかのカードと同じく文字のままにした。
- `MoreDetails` はブラウザ標準の `<dialog>`（`showModal()`）なので、Esc・閉じるボタン・背景のクリックで閉じ、開いている間は背後を操作できない。
- 制作物の記事がある出来事は、従来どおり記事（`/products/slug`）へのリンク。
- `/history/[id]` のページは、外部からの直接リンクとサイトマップのために残している。

**編集画面のプレビュー**: 年表エディタの右側（以前は本文の Markdown だけを表示し、空のときは「詳細ページの本文がここに表示されます」と出ていた）に、年表で開くポップアップと同じ見た目のプレビューを出すようにした。

- `MoreDetails` の中身を `MoreDetailsBody` として、外枠のクラスを `MORE_DETAILS_PANEL_CLASS` として切り出した。ポップアップに入れる部品（画像・見出しの下の情報・本文）も `historyDetailParts` にまとめた。
- 実物とプレビューの両方でこれらを使うので、見た目が常に一致する。
- プレビューの背景は、実物と同じ黒 50%＋ぼかし。閉じるボタンは押せない見本。

サイトの CSS を当てた単体の画面で、実物のポップアップとプレビューを撮影して比べ、同じ見た目になることを確かめた。

**確認したこと**: 今のデータには「制作物の記事がなく、詳細がある出来事」がない（詳細のある 11 件はすべて制作物の記事につながっている）。本番の DB にテスト用の出来事を作るのは避け、部品だけを単体で動かして確かめた。

### 12. 年表の出来事からリンクする記事を、カードの一覧から選ぶ（追加対応）

**概要と原因**: 年表の編集画面では、リンクする制作物の記事を slug の直接入力で指定していた。リンクできるのも制作物の記事だけだった。

**放置するとどうなるか**: slug を覚えていないと入力できない。打ち間違えると、存在しない記事へのリンク（404）になる。学校・活動・仕事の出来事は、ブログの記事があってもリンクできない。

**対処**:

- [`HistoryArticlePicker.tsx`](../src/components/HistoryArticlePicker.tsx) を作った。公開中の記事をカード（サムネイル・タイトル・説明）の一覧で表示し、押すと選択できる。選択中の記事は `aria-pressed` で伝え、ダイアログには `useDialog` を使う。「リンクを外す」も置いた。公開中の記事に見つからない slug（下書きに戻した・削除したなど）は、そのことを赤字で示す。
- リンク先のジャンルを種類で決める（[`src/lib/history.ts`](../src/lib/history.ts) の `historyArticleGenre` / `historyArticleHref`）。「技術・開発・資格」は制作物（`/products/slug`）、「学校・活動・仕事」はブログ（`/blogs/slug`）。DB の `product_slug` 列は「リンクする記事の slug」として使い、列は増やしていない（既存のリンクはすべて「技術」→ 制作物なので、そのまま動く）。
- 編集画面で種類を変えると、選んでいた記事は外す（残すと、制作物の slug のままブログの記事へリンクしてしまうため）。
- 候補は [`select.ts`](../src/db/queries/select.ts) の `getHistoryArticleCandidates` で取得し、管理画面の作成・編集ページから渡す。公開中の制作物とブログを、カードに出す列だけ1回の問い合わせで取り、ジャンルごとに振り分ける（最初は記事一覧用の `getPostsList` をジャンルごとに2回呼んでいたが、問い合わせが2回になり、使わないタグの結合・集計も行っていたため改めた）。DB への問い合わせが増えるのは年表の作成・編集ページを開いたときの1回だけで、公開ページは増えていない。
- 年表のカードは「制作物の記事を読む →」「ブログの記事を読む →」を出し分ける。`/history/[id]` を直接開いたときのリダイレクト先も、種類に合わせた記事にした。

**未確認**: 管理画面のためブラウザでは確認していない（型チェック・lint のみ）。
