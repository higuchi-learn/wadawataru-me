# OG画像のブランド表記変更がデプロイしても反映されない問題

- 対応日: 2026-09-03
- 関連コミット: `c182d47`
- 前提: `documents/og-image-caching-fix.md`（`/api/og` にCache APIを導入した対応）

## 何が問題だったか

サイト名を「わだわたるKIN TV」から「わだわたるのログマガ」に変更するのに合わせて、自動生成サムネイル（`/api/og`）内のブランド表記も「わだわたるKIN TV」から「わだわたる」に変更してデプロイした。しかし、実際に見た目を確認すると**表記が「わだわたるKIN TV」のまま変わっていなかった**。

## 何が原因だったか

直前の対応（`og-image-caching-fix.md`）で `/api/og` に `caches.default`（Cloudflare Cache API）を使ったエッジキャッシュを導入し、`Cache-Control: public, max-age=31536000, immutable`（1年間キャッシュ）を付けていた。

このキャッシュのキーは**リクエストURL（`/api/og?title=...`）そのもの**だったため、ブランド表記を変えるコード修正をデプロイしても、**同じURLへのキャッシュエントリはそのまま**残ってしまう。しかもCloudflareのキャッシュは世界中のエッジ拠点ごとに個別に保持されるため、

- 検証で使っていた拠点: たまたまキャッシュされていなかった（または古いキャッシュが自然に切れていた）ので新しい画像が返り、正しく修正されたように見えた
- 実際にサイトを見たユーザーがアクセスした拠点: 修正前にキャッシュされた「KIN TV」の画像がまだ1年キャッシュとして残っていたため、そのまま返り続けた

という「拠点によって新旧が混在する」状態になっていた。**デプロイ自体は正しく反映されていたが、キャッシュが古いレスポンスを返し続けていた**のが直接の原因。

## どう対処したか

[src/app/api/og/route.tsx](../src/app/api/og/route.tsx)

キャッシュのキーに `OG_IMAGE_VERSION` という定数を含めるようにした。

```ts
const OG_IMAGE_VERSION = 2;

const cacheKeyUrl = new URL(request.url);
cacheKeyUrl.searchParams.set('v', String(OG_IMAGE_VERSION));
const cacheKey = new Request(cacheKeyUrl, request);
```

外部に公開する `og:image` のURL自体（`/api/og?title=...`）は変えず、**キャッシュの内部キーだけ**にバージョンを足している。今後、画像のレイアウトやブランド表記など見た目に関わる変更をしたときは、この `OG_IMAGE_VERSION` を1つ上げることで、全拠点のキャッシュを一括して無効化（＝強制的にキャッシュミスさせて再生成）できるようにした。コード上にもその旨のコメントを残した。

## 現状

- デプロイ後、本番で実際に画像を取得し「わだわたる」の表記になっていることを確認済み
- 今後、`/api/og` の見た目に関わる変更をする際は `OG_IMAGE_VERSION` を上げ忘れないようにする必要がある（上げ忘れると今回と同じ「デプロイしたのに反映されない」状態が再発する）
